# API

Базовый URL: `https://app.kombinator.ru/`

Аутентификация — JWT Bearer-токен. Токен получается через `Account/Login` и передается в заголовке:

```
Authorization: Bearer {accessToken}
```

## 1. Аутентификация: `POST /api/v3/Account/Login`

Вход по email и паролю. Доступен анонимно, предварительная аутентификация не требуется.
При успехе возвращает пару токенов (access + refresh) и дополнительно выставляет refresh-token cookie.

### Тело запроса

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `email` | string | да | Email учетной записи |
| `password` | string | да | Пароль |

### Пример запроса

```http
POST https://app.kombinator.ru/api/v3/Account/Login
content-type: application/json

{
  "email": "user@example.com",
  "password": "password"
}
```

### Ответ 200

| Поле | Тип | Описание |
|---|---|---|
| `profile` | object | Информация о профиле учетной записи |
| `accessToken` | string | JWT access-токен для заголовка `Authorization` |
| `accessExpiresAt` | date-time | Время истечения access-токена |
| `refreshToken` | string | Refresh-токен для продления сессии |
| `refreshExpiresAt` | date-time | Время истечения refresh-токена |

### Ошибки

| Код | Описание |
|---|---|
| 404 | Учетная запись не найдена |
| 422 | Ошибка валидации / неверные учетные данные |
| 500 | Внутренняя ошибка сервера |

## 2. Генерация документа: `POST /api/v3/Templates/Files/{TemplateId}/Generate`

Заполняет шаблон данными и генерирует документ в запрошенном формате. Может разбивать
результат на отдельные поддокументы и возвращать их zip-архивом, если это предусмотренно шаблоном.

**Заголовок:** `Authorization: Bearer {accessToken}`

### Параметры пути

| Параметр | Тип | Описание |
|---|---|---|
| `TemplateId` | int32 | Идентификатор шаблона |

### Тело запроса

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `data` | object | да | Словарь значений полей анкеты [(см. раздел «Формат поля data»)](#data) |
| `format` | string | да | "docx" или "pdf" |

## Формат поля `data`

Поле `data` — это словарь «идентификатор поля → значение», где ключи соответствуют
идентификаторам полей анкеты документа. 

```json
"data": 
     {
        "<наименование простого поля>": "<значение поля>",
         "<наименование составного поля>" :
         [
            {
              "<наименование вложенного поля>": "<значение вложенного поля>", …
            } ,
             …
         ]
      }
```

***Обратите внимание:***

- **Группы не создают пространства имен.** Поля анкеты могут быть объединены в «Группы»,
   но группа служит исключительно для визуального разделения в анкете. Все поля группы
   передаются в `data` на верхнем уровне, без вложенности.
- **Регистр символов не важен.** Идентификаторы полей в JSON не учитывают регистр
- **Логические значения** (поля «Да/Нет») принимают значения `true` и `false`.

```json
"data": {
   …
  "включаяНДС": true,
   …
}
```

- **Числа** передаются в стандартной JSON-нотации (числом, не строкой); разделителем
   дробной части всегда служит точка: `1001.11`.

```json
"data": {
   …
  "цена": 20.7,
   …
}
```

- **Списки** передаются в стандартной JSON-нотации — массивом объектов. Идентификатор
   элемента списка из анкеты использовать не нужно.

```json
"data": {
  "Заказ": [
    { "товарнаяПозиция": "печенье", "цена": 525 },
    { "товарнаяПозиция": "макароны", "цена": 271 },
  ]
}
```

- **Даты** и **Время** задаются в формате ISO8601

```json
"data": {
   …
   "датаРождения": "1980-01-27",
   …
}
```
